# FOLI 固件

[English](README.md)

ESP32 / Arduino / FreeRTOS 固件，保持旧版五字节命令与四字节状态协议。整合版本进行了编译与主机回归检查，**本次没有烧录，也没有重新做实物打印验证**。

## 构建

```sh
python -m pip install platformio==6.2.0
pio run --project-dir software/firmware
```

平台固定为 `espressif32@7.0.1`。已安装参考环境对应 Arduino-ESP32 2.0.17，包版本 `3.20017.241212+sha.dcc1105b` 的开头数字不代表 Arduino 3.x。烧录前独立核对硬件与引脚；CI 不触发烧录。Windows 中文路径可能触发交叉编译器响应文件错误，可用 ASCII 路径或将同目录临时映射为驱动器路径。

## 修复内容

- A6 结束命令不再误入打印队列。
- BLE 任意分片按 48 字节组行为完整数据；空任务、尾部不足一行、队列溢出在 A6 时拒绝，避免默默补脏数据。
- 队列写入、读取、清空和计数统一加锁；读取复制到消费者缓冲，避免返回已释放队列槽指针。
- 主循环主动让出调度，按键任务可运行；毫秒延迟明确转换为 ticks。
- 加热前检查缺纸/温度，队列打印每 16 行刷新传感器；所有打印退出路径关闭升压、STB 并停止电机、清理残留。异常不再继续正常尾部走纸，关闭输出先于阻塞的提示动作。
- 电量在转换到无符号数前限幅；打印/完成锁存期间拒收新的写入；空闲断开连接清理未完成任务；数值为 0 的启动宏正确选择分支。

## 协议与剩余边界

每行 384 点、48 字节、MSB 优先。A5×4 后密度字节对应 30/60/100%；A6×4 后一字节结束接收。状态为电量、温度、纸张（0 有纸 / 1 缺纸）、打印状态（0 初始化 / 1 开始 / 2 工作枚举 / 3 返回或停止）。旧实现不保证发送 working 状态，也没有独立的失败结束状态；FINISH 不能证明实物成功打印。

队列 1000 行，Android 主动限制为 768 行。旧协议中恰好五字节并匹配命令前缀的光栅分片仍有歧义；Android 在协商 MTU 后按整行发送。没有任务 ID、CRC、逐行确认或可靠远程取消。溢出拒绝没有专用错误包，不能盲目重发不确定的任务。

20 秒打印超时保持不变，超时锁存后需重启。保留原有加热补偿公式和时序，未声明其物理效果已经复测。NTC 开短路诊断、校准尚未建立，空闲 0℃ 不能当作有效温度证据。这些软件检查不构成经认证的安全系统。

引脚配置与完整主机测试命令见英文页。源码能证实 GPIO 与协议常量，不能仅凭源码确定最终电池容量、FPC 位数。主机测试覆盖实际共享命令/行缓冲代码，包括不同分片边界、回绕、溢出与清空，不代替无线、任务调度、电气和纸面质量验证。

2026-10-30 本地结果：PlatformIO 6.2.0 / 平台 7.0.1 编译通过，RAM 88,012 / 327,680 字节，Flash 1,151,101 / 1,310,720 字节。Zig 0.13 编译执行 C++11 主机测试通过。远端 CI 结果独立报告；本次没有执行 upload。

本次仅支持默认的收完再打模式（`START_PRINTER_WHEN_FINISH_RAED=1`）。旧流式分支保留作参考，但打印期间写入被拒绝，不应开启并声称已支持。
