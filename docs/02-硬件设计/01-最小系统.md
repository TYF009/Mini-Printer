# 02-硬件设计 · 01 · ESP32 最小系统与下载调试电路

## 1. 最小系统的痛点

ESP32 最小系统（模组 + 供电 + 去耦 + 启动配置）只能让芯片"跑起来"，调试并不方便：

- 烧录需要外购 USB 转 TTL 模块 + 杜邦线飞线
- IO0、EN 引脚需要单独引出，手动短接进下载模式
- 没有板载供电，每次调试都要接线

因此在本项目中做了两项针对性优化：**① 板载 USB 供电/烧录/调试电路；② 自动下载电路**——插一根 Type-C 线即可完成供电、烧录、串口监视全流程。

## 2. USB 供电、烧录、调试电路

模组的下载接口是 UART（VCC 3.3V / TX / RX / GND），而 Type-C 口提供的是 5V 电源 + USB 差分信号，因此需要三个子电路：Type-C 接口、5V→3.3V 电压转换、USB 转串口。

### 2.1 Type-C 接口（U2，20009-UCAF001-X）

- **VBUS**：电源端，接电脑 USB 或充电器时为 5V
- **CC1/CC2 各经 5.1kΩ 电阻下拉到地**：Type-C 的接入检测与正反插识别。本设备是**受电设备（UFP）**角色，CC 下拉电阻就是向充电器"表明身份"的——若 CC 悬空，充电器会认为没有设备接入而不输出 VBUS，这是 Type-C 与老式 USB 最大的区别，也是最常踩的坑
- **UD+/UD-**：数据线，A/B 两面引脚对称连接，支持正反插
- SBU1/SBU2 空置（USB2.0 场景不用）

整机版在 D+/D- 上另加了 ESD 保护（CESD5V0D3），防止插拔静电损坏后级。

### 2.2 电压转换：XC6210B332MR LDO（U3）

- **需求**：Type-C 输入 5V，芯片需 3.3V，输出电流 500mA 以上
- **方案**：XC6210B332MR 固定 3.3V 输出 LDO，SOT-23 封装，最大 700mA
- **外围极简**：输入、输出各 1μF 陶瓷旁路电容；CE 引脚接输入电源（上电即工作，常使能）

> 整机版注意：LDO 的输入端实际取自电池路径 VBAT_OUT（USB 的 5V 经充电芯片给电池供电，详见《02-电源架构》）——即整机由电池统一供 3.3V，USB 只负责充电与数据。

### 2.3 USB 转串口：CH340C（U4）

ESP32 的下载/调试引脚是串口，Type-C 进来的是 USB 信号，中间用 **CH340C** 完成协议转换：

- VCC 接 3.3V，V3 接 3.3V（内部电源参考）
- UD+ / UD- 对接 Type-C 数据线
- TXD/RXD 对接 ESP32 的 RXD0/TXD0
- **DTR#/RTS# 引出**——这是选 CH340C 的关键：这两个流控脚是自动下载电路的控制信号来源
- CH340C **内置晶振**，无需外部晶体（这也是选 C 后缀型号而非 CH340N 等需要斟酌的点）

## 3. 自动下载电路（Q1/Q25，SS8050 ×2）

### 3.1 下载模式的进入条件

ESP32 进入串口下载模式的前提：**IO0 拉低 + EN 产生一次复位（低→高上升沿）**。复位后芯片检测 GPIO0 为低电平，自动进入下载启动模式。手动做法是按住 BOOT 键再按 EN 键——自动下载电路就是让 CH340 的 DTR/RTS 替你"按"这两个键。

### 3.2 电路结构：交叉耦合双 NPN

两颗 SS8050 NPN 三极管交叉连接（学习版位号 Q1/Q2，整机版 Q1/Q25）：

- Q1：基极经 10kΩ 接 **RTS**，发射极接 **DTR**，集电极接 **IO0**
- Q2：基极经 10kΩ 接 **DTR**，发射极接 **RTS**，集电极接 **EN**

三极管导通条件是 b-e 间有正向压差，于是：

| DTR | RTS | Q1（→IO0） | Q2（→EN） | 效果 |
|---|---|---|---|---|
| 0 | 1 | 导通 | 截止 | **IO0 拉低** |
| 1 | 0 | 截止 | 导通 | **EN 拉低（复位）** |
| 0 | 0 | 截止 | 截止 | 两者都释放（高电平，上拉维持） |
| 1 | 1 | 截止 | 截止 | 两者都释放 |

### 3.3 设计精髓：为什么必须交叉耦合

注意真值表最后两行：**当 DTR 与 RTS 电平相同时，两个三极管的基极和发射极等电位，全都截止**。普通串口通信时 DTR/RTS 常被同时置位（如某些终端软件默认断言两者），如果用直连电路，插上串口就会意外复位芯片、拉低 IO0。交叉耦合保证了"两信号相同 → 什么也不发生"，只有 esptool **刻意输出互斥电平序列**（先 DTR=0/RTS=1 拉低 IO0，再 DTR=1/RTS=0 复位，最后释放）才会进下载模式——这就是"自动下载"的全部秘密。

## 5. 小结

本模块的收益：一根 Type-C 线完成供电 + 烧录 + 串口监视，`pio run -t upload` 直接可用，无需任何手动操作。这背后是三个知识点：Type-C UFP 的 CC 下拉识别、LDO 最简应用电路、DTR/RTS 交叉耦合自动下载——第三点是 ESP32 硬件面试的高频题，务必能画出电路并解释真值表。
