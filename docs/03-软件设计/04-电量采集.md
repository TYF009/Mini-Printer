# 03-软件设计 · 04 · 电量采集

## 1. 需求与原理

电池供电产品，需要把电池剩余电量告知用户（App 显示、低电提醒）。硬件是 10k+10k 分压（见 02-硬件设计/03），ADC 读分压值反推电池电压，再按电压区间估算百分比。

## 2. 电压→电量换算链

```
ADC 原始值(0~4095, 12bit) ──校准换算──> 采样点电压(mV) ──×2(分压比)──> 电池电压
电池电压 ──map 线性映射──> 0~100% 电量
```

- 电池满电 4.2V、缺电约 3.3V；1:1 分压后采样点为 2.1V~1.65V
- 换算到电池侧，即把 3.3V~4.2V 的电压线性映射到 0~100（`map()` 实现）
- 采集周期：学习版 1s 一次；整机固件由状态轮询任务统一调度，10s 周期（对电量这种慢变量足够）

## 3. ADC 精度问题（本项目踩坑点，面试重点）

**现象**：实测 ADC 读值换算的电压与万用表实测偏差较大。

**原因与解决**：查 ESP32 技术手册——**ADC1 带出厂 eFuse 校准**，每颗芯片的 ADC 非线性曲线在出厂时写入了 eFuse。两种用法：

```cpp
// 方式一：原始值 + 手动校准换算
uint32_t mV = esp_adc_cal_raw_to_voltage(raw, &adc_chars);
// 方式二（本项目采用）：直接读校准后的毫伏值
uint32_t mV = analogReadMilliVolts(PIN_POWER_ADC);
```

**进一步提高精度的手段**（按性价比排序）：

1. 高精度分压电阻（1% 及以上）——分压误差直接进入电压结果
2. ADC 输入端加 100nF 陶瓷旁路电容（硬件已有，滤除噪声）
3. 多次采样滤波（中值/滑动平均）——固件暂未实现，为已知改进项
4. 更精细的校准算法（分段查表修正）

> 已知缺陷（known-issues #3）：map 在电池 <3.3V 时输出负数、经 uint8_t 回绕被上限钳成 100%——"越没电越显示满电"，修复见 04-项目整合。
