# 03-软件设计 · 01 · 工程结构与任务模型

## 1. 工程结构

PlatformIO + Arduino 框架（Arduino-ESP32 core 底层即 FreeRTOS + ESP-IDF HAL），源码按模块分层：

```
src/
├── main.cpp        初始化与任务创建入口
├── em_task.cpp/.h  打印业务状态机（打印启动条件、按键响应、状态上报）
├── em_device.cpp/.h 设备状态结构（电量/温度/纸/打印状态）
├── hal/            硬件抽象层
│   ├── em_ble      BLE 服务端与收发回调
│   ├── em_printer  打印头驱动（SPI/LAT/STB 时序）
│   ├── em_motor    步进电机四相八拍驱动
│   ├── em_adc      电量/温度 ADC 采集换算
│   ├── em_button   按键状态机
│   ├── em_timer    状态轮询与打印超时定时器
│   └── em_spi      HSPI 初始化
└── utils/
    └── em_queue    环形打印缓冲（详见 02-消息队列）
```

分层原则：业务（em_task）不直接摸寄存器，硬件操作全部收敛在 hal/，换板卡只改 hal 层与引脚配置（em_config.h 中按 V2/V3/V4 板卡版本区分引脚组）。

## 2. 任务模型（FreeRTOS）

系统三个并发执行流 + 两类异步源：

| 任务 | 优先级 | 周期/触发 | 职责 |
|---|---|---|---|
| loopTask（打印主任务） | 1 | 常驻 | `loop()` 调 `printer_run()` 打印状态机 |
| task_report | 1 | 100ms 轮询 | 传感器采集 + BLE 状态上报 + 缺纸事件处理 |
| task_button | 0 | 10ms 轮询 | 按键消抖与长短按识别 |
| Ticker（esp_timer） | — | 2ms / 10s / 20s | 电机步进节拍 / 状态刷新 / 打印超时 |
| GPIO 中断 | — | 上升沿 | 缺纸检测（置事件标志） |

设计要点：

1. **中断/定时器回调只置标志不做重活**（need_report、read_state_timeout 等），业务由任务轮询标志后慢慢做——中断上下文里不能执行耗时操作（尤其 BLE 栈操作），这是嵌入式的通用纪律
2. **三个任务各管一摊、优先级两档**：打印与上报同级轮转，按键最低优先级容忍延迟；跨任务共享的打印缓冲用互斥锁保护，共享状态变量依赖任务轮询天然同步
3. **Ticker 与任务各司其职**：电机 2ms 节拍用 Ticker（精度要求高、回调极短），状态采集用任务轮询（需要执行 ADC 换算和 BLE 上报，放任务里做）

> 已知待改进项（详见 docs/known-issues.md）：打印状态机的忙等未让出 CPU 会饿死按键任务；部分跨任务变量缺 volatile——这些是初版实现的缺陷，也是本项目"问题与修复"章节的素材。
