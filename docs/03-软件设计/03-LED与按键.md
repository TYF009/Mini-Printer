# 03-软件设计 · 03 · LED 指示与按键状态机

> 实验 安全提示：非打印头相关的实验（LED、按键、电量）不要接打印头。

## 1. LED 状态指示（hal/em_button.cpp::run_led 等）

**需求**：无屏幕设备，用一颗 LED 的四种状态表达设备状态：

| 状态 | 灯光 |
|---|---|
| 待机 | 暗 |
| 蓝牙连接 | 常亮 |
| 运行异常 | 快闪 |
| 打印中 | 慢闪 |

**实现**：提供统一接口 `run_led(模式)`，内部用 delay 序列拼出四种波形（常亮=持续输出；快闪/慢闪=不同占空比/周期的方波；暗=熄灭）。硬件为 IO18 低电平点亮 + 1kΩ 限流。

> 已知缺陷：delay 串联实现最长阻塞约 0.5s，会拖慢打印循环（known-issues #8），改进方向是改成 ticker 节拍的非阻塞闪烁。

## 2. 按键状态机（hal/em_button.cpp）

**需求**：识别**短按 / 长按按下 / 长按释放**三种事件。业务映射：短按→打印测试，长按→电机转动开始，长按释放→电机停转。

**实现原理**（10ms 轮询 + 二次确认消抖）：

```
初始化 IO 为输入
每 10ms 读取 IO：
  读到按下电平 → 10ms 后再读一次（去抖二次确认）
  仍为按下 → 确认"按下"，记录按下时间 t0
  之后每 10ms 复读：
    持续按下 且 (now - t0) > 1s → 触发【长按事件】（仅一次）
    读到抬起电平：
      按下时长 > 1s → 触发【长按释放事件】
      否则          → 触发【短按事件】
```

关键点：

1. **二次确认消抖**：机械按键抖动 5~10ms，第一次读到按下后隔 10ms 再读，两次都按下才算真按下——比"连续 N 次计数"实现更简单且等效；硬件侧另有 RC 消抖（见 02-硬件设计/03），双保险
2. **长按一次性触发**：长按事件在跨越 1s 阈值时触发一次（用标志位防止每个轮询周期重复触发），长按释放事件在松手时触发——"开始转动/停止转动"的语义正好对应
3. 按键任务优先级最低（0），10ms 轮询对按键这种慢速输入绰绰有余
