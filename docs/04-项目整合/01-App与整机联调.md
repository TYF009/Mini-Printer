# 04-项目整合 · 01 · 手机 App 与整机联调

## 1. App 说明

手机端 App 直接使用**小智学长开源的 Mini-Printer App**（本项目聚焦硬件与固件，App 不做二次开发，在此感谢开源）。App 完成图片选取、编辑排版、二值化处理与 BLE 发送，固件侧与 App 通过下述协议对接。

## 2. 通信协议总览（App ↔ 固件）

基于 BLE 透传，1 个自定义服务 + 1 个特征（UUID 与固件一致）：

```c
#define SERVICE_UUID        "4fafc201-1fb5-459e-8fcc-c5c9c331914b"
#define CHARACTERISTIC_UUID "beb5483e-36e1-4688-b7f5-ea07361b26a8"
#define BLE_NAME            "Mini-Printer"
```

共四类数据：

| 类型 | 方向 | 载体 |
|---|---|---|
| 设备状态上报 | 设备→App | Notify |
| 打印数据（点阵） | App→设备 | Write |
| 颜色深度设置 | App→设备 | Write（A5 命令） |
| 开始打印指令 | App→设备 | Write（A6 命令） |

### 2.1 设备状态上报（Notify）

4 字节：`[0]电量 [1]打印头温度 [2]缺纸状态 [3]打印状态`。连接成功后 App 订阅通知并解析显示。

> 协议已知不足：状态包**没有包头与校验码**，严格来说必须加上（误包/粘包时 App 侧无从校验）——列为待改进项。

### 2.2 打印数据发送（App 侧处理链）

```
原图 → 抖动算法转灰阶图 → 缩放到指定宽度（384px）→ 二值化 → 打包行数据 → BLE 分包下发
```

- **二值化**：每个像素与阈值比较（默认 100），大于为白（0，不打印）、小于为黑（1，打印）
- **打包**：8 个点合 1 字节（如 `00010001` = 0x11），一行 384 点 = 48 字节，即一条打印数据
- **发送节奏**：一张图几十到上百行，受 BLE 速率限制，**每条指令间隔 1~10ms**（实测调优值）——太快设备侧环形缓冲会溢出丢行

### 2.3 颜色深度设置

`A5 A5 A5 A5 nn`，nn=01/02/03 对应低/中/高三档浓度（固件映射 30%/60%/100% 加热时长）。

### 2.4 开始打印指令

`A6 A6 A6 A6 01`，App 发完全部打印数据后发送。

**这条指令的由来（联调踩坑）**：部分较老的 Android 手机用蓝牙 4.0 协议栈，发送速度慢——**打印速度比接收数据速度还快**，导致打印不完整或一卡一卡。因此把"边收边打"改为"收完再打"：App 发完所有数据后补一条 A6，设备收到才开始打印。这是"应用层结束标志"设计的现实动机（也是本项目防丢包设计的核心一环）。

## 3. 固件侧打印启动逻辑

```c
#ifdef START_PRINTER_WHEN_FINISH_RAED
    // 模式一（默认）：收到 A6（read_ble_finish）才打印
    if (pdevice->read_ble_finish == true) {
        if (printer_state == FINISH || printer_state == INIT) {
            read_ble_finish = false;
            printer_state = PRINTER_STATUS_START;
            ble_report();          // BLE 上报"开始打印"
            run_beep(BEEP_PRINTER_START);
            run_led(LED_PRINTER_START);
        }
    }
#else
    // 模式二：缓冲攒够 100 行即开打（边收边打，适合快协议栈手机）
    if (get_ble_rx_leftline() > 100) { ...同上状态迁移... }
#endif
```

两种模式各有适用面：慢协议栈手机用模式一保证完整；快协议栈手机可用模式二缩短首行出纸时间。两种模式固件均已实现，编译开关切换。

## 4. 联调验证要点（checklist）

1. LightBlue 手动写 A5/A6 命令、订阅 Notify——先脱开 App 验证固件协议
2. App 连接后先发一张小图（几十行），确认起止行完整、无错位
3. 观察缺纸/温度异常时 App 是否正确收到状态并提示
4. 慢手机（BLE 4.0 栈）上验证 A6 模式打印完整性
5. 打印中途断开蓝牙，验证 20s 超时兜底退出
